# SMC + Pro Support Resistance — MTF Signals v1.12

ตัวเสริม MT5 สำหรับทดลองสัญญาณ Entry/SL/TP หลาย Timeframe ไม่มีคำสั่งเปิด ปิด หรือจัดการออร์เดอร์จริง

## แก้ CLOCK_ERROR — v1.12

แก้กรณีกราฟมี quote ใหม่ แต่แผง v1.11 ขึ้น “เวลา quote ผิดปกติ” เพราะใช้ `TimeTradeServer()` เป็นเวลาอ้างอิง ซึ่งเป็นเวลาประมาณที่ Terminal คำนวณและขึ้นกับการตั้งเวลาเครื่อง

รุ่นนี้อิง `TimeCurrent()` ที่รับจากโบรกเกอร์ และใช้ `GetTickCount64()` จับเวลาที่ผ่านไปเมื่อไม่มี tick ใหม่ ใช้หลักเดียวกันทั้งหน้าจอ รอบสแกน การแตะโซน และการตรวจ quote ก่อนสัญญาณ ไม่เพิ่มเพดานอายุ quote เพื่อให้ผ่าน และไม่ปรับเวลาหรือ timezone ของ Windows

ตอนเริ่มหรือหลังตรวจพบการขาดการเชื่อมต่อ จะขึ้น **รอเวลาโบรกเกอร์** จนเห็นเวลา server ขยับ หากไม่มี tick ใหม่ยังไม่เริ่มประเมินสัญญาณ ขณะรอครั้งแรกจึงอาจยังแยกว่าเป็นนอกช่วงรับราคาไม่ได้ ส่วนราคาที่หยุดระหว่างใช้งานยังหมดอายุตาม `MaxQuoteAgeSeconds` แม้ TimeCurrent จะหยุดตามด้วย

เพิ่ม Log `QUOTE_HEALTH` เมื่อสถานะเปลี่ยน โดยบันทึก `received` (เวลาโบรกเกอร์), `quote`, `checked_at` (เวลาที่ใช้ตรวจ), และ `local_estimate` (TimeTradeServer ใช้เพื่อวินิจฉัยเท่านั้น) ถ้ายังพบอาการให้ตรวจบรรทัดนี้ใน Experts

อ้างอิง MetaQuotes: [TimeTradeServer](https://www.mql5.com/en/docs/dateandtime/timetradeserver), [TimeCurrent](https://www.mql5.com/en/docs/dateandtime/timecurrent), [GetTickCount64](https://www.mql5.com/en/docs/common/gettickcount64)

## แผงกะทัดรัดแบบที่ 1 — v1.12

เปลี่ยนข้อความยาวที่ทับแท่งเทียนเป็นแผงพื้นทึบสีเข้ม ใช้ข้อความไทยและตัวเลขราคาเรียงชิดขวา แผงสร้างด้วย Chart Objects ของ MT5 ไม่ต้องเปิดหน้าเว็บ แสดงสถานะข้อมูล สิ่งที่กำลังรอ และแผน Entry / SL / TP1–3 เมื่อมีสัญญาณ ปุ่ม **ย่อ / ขยาย** ลดพื้นที่บังกราฟ และปุ่ม **รายละเอียด / กลับหน้าหลัก** สลับมุมมองต้นทาง H4/H1/M15/M5/M1 กับผลตรวจล่าสุด

## กฎสัญญาณเดิมจาก v1.10: แตะโซน → M1 ยืนยันกลับตัว → Entry/SL/TP

เพิ่มโหมด `M1_ZONE_CONFIRM` ตามตัวเลือก M1 ยืนยันกลับตัว โดยไม่ต้องรอ M5 CHoCH และ M1 retest เพิ่มทุกครั้ง ระบบ Strict Sweep เดิมยังอยู่ ส่วน Zone Observer เดิมยังเป็นการสังเกตเท่านั้น เลข v1.10 ใช้แยกรุ่นนี้จากแผน Paper Performance v1.07 ซึ่งยังไม่ได้ทำ

โหมดใหม่ใช้โซน M15 และ M5 ที่อ่านได้จาก Indicator ต้นทาง รวมถึงโซนรอบ swing M1 ที่คำนวณจากแท่งปิด จุด swing ต้องมีแท่งยืนยัน 2 แท่งแต่ละด้านก่อนจะนำมาใช้ โซนแบบนี้ระบุชื่อ `M1_SWING_BUY/SELL` ชัดเจน ไม่ใช่โซน SSSR จากต้นทาง

ภาพตัวอย่างใช้เป็นแนวทางของการย่อกลับโซนและกลับตัวตามโครงสร้างราคาเท่านั้น รุ่นนี้ไม่ได้ลอกตำแหน่งออร์เดอร์ในภาพ ไม่ใช้ RSI, MACD หรือเส้นอื่นในภาพเป็นเงื่อนไข และยังไม่ได้พิสูจน์ว่าให้ผลตรงทุกภาพหรือมีกำไร

### กฎ BUY / SELL แบบตรวจสอบได้

| ขั้น | BUY ที่ Support | SELL ที่ Resistance |
|---|---|---|
| เตรียมโซน | เคยมีราคาปิดเหนือขอบบนมากกว่า 1 tick หลังระบบรู้จักโซน | เคยมีราคาปิดต่ำกว่าขอบล่างมากกว่า 1 tick หลังระบบรู้จักโซน |
| แตะ | ช่วง High–Low ของ M1 ที่ปิดแล้วซ้อนกับโซน | เงื่อนไขเดียวกัน |
| ล็อก trigger | swing high M1 ล่าสุดที่เข้าเกณฑ์ 2 แท่งซ้าย/1 แท่งขวา ยืนยันก่อนแท่งแตะ และอยู่เหนือ Close แท่งก่อนแตะ | swing low เกณฑ์เดียวกัน อยู่ต่ำกว่า Close แท่งก่อนแตะ |
| ยืนยัน | แท่งเขียวปิดเหนือ trigger และขอบบนโซน + buffer โดย body ผ่านขั้นต่ำ | แท่งแดงปิดต่ำกว่า trigger และขอบล่างโซน − buffer โดย body ผ่านขั้นต่ำ |
| Entry | Ask ปัจจุบันหลังยืนยันและข้อมูลยังสด | Bid ปัจจุบันหลังยืนยันและข้อมูลยังสด |
| SL | ต่ำกว่า Low ต่ำสุดตั้งแต่แท่งแตะจนถึงแท่งยืนยัน − buffer SL | สูงกว่า High สูงสุดช่วงเดียวกัน + buffer SL |
| ยกเลิก | ปิดทะลุขอบล่าง − buffer ก่อนยืนยัน หรือหมดเวลา | ปิดทะลุขอบบน + buffer ก่อนยืนยัน หรือหมดเวลา |

แท่งแตะสามารถเป็นแท่งยืนยันได้ หากครบทุกเงื่อนไขเมื่อปิดแท่ง ไม่มีการเข้าเพียงเพราะไส้เทียนแตะ ไม่ต้องมี sweep เป็นเงื่อนไขบังคับของโหมด M1 นี้ และการข้ามขอบโซนอย่างเดียวไม่ถูกเรียกว่า BOS โดยอัตโนมัติ

SL buffer = max(0.15 × ATR M1, 2 × spread, 2 ticks) ตามค่าเริ่มต้น TP1 = 1R, TP2 = 2R, TP3 ไม่เกิน 3R และถูกจำกัดตามพื้นที่ก่อนโซนฝั่งตรงข้าม H4/H1/M15 การปัดราคาใช้ tick size

ตัวกรอง Entry ที่ยังคงอยู่: risk อย่างน้อย 2 ticks, spread/risk ไม่เกิน 20%, Entry ห่าง Close แท่งยืนยันไม่เกิน 0.5 ATR M1 และพื้นที่ก่อนโซนฝั่งตรงข้ามต้องพอถึง TP2 กรณีใกล้ขอบอาจถูกปฏิเสธจากการปัดราคา

ข้อจำกัดการคำนวณ room ในรุ่นนี้: ยังพิจารณาเฉพาะโซนต้นทาง H4/H1/M15 ไม่รวม M5 หรือ swing M1 เป็นอุปสรรค TP และยังไม่หักค่าคอมมิชชันหรือ slippage

| `FAST_END ... PLAN_ACTIVE` | มีแผนหนึ่งทำงานอยู่แล้ว จึงไม่ออกแผนซ้อน |
| `FAST_END ... COOLDOWN` | อยู่ในช่วงพัก |
| `FAST_END ... SETUP_EXPIRED` | ไม่ยืนยันภายในเวลารอ |
| `FAST_SOURCE_FROZEN` | ต้นทางเปลี่ยน/หาย แต่เก็บขอบเดิมของ setup ที่แตะแล้วจนถึงเส้นตายเดิม |
| `WAIT_SYNC` / `STALE_SCAN` | ข้อมูลยังไม่พร้อมหรือการสแกนค้าง ไม่ใช่ “ตลาดไม่มี setup” |

บรรทัด `M1: ...` ด้านบนแสดงสถานะปัจจุบัน ส่วนบรรทัดล่าง `FAST_...` เป็นเหตุการณ์ล่าสุด เลื่อนเมาส์บนสถานะด้านล่างเพื่อดู setup ID, trigger และ deadline ของ setup ที่กำลังรอ พร้อมรายละเอียดเต็มใน Audit

ระหว่าง tick สามารถแสดงจุดแตะได้ แต่ลูกศร Entry ใช้แท่งปิดผ่านรอบ Timer (ทุก 2 วินาที มี warmup ต้นนาทีและเวลาสแกนต้นทาง) จึงไม่ใช่ entry ภายในแท่ง และไม่รับประกันความหน่วงคงที่หาก MT5 เรียกข้อมูลช้า

### การติดตามแผนและการป้องกันย้อนหลัง

- ใช้ขอบโซนที่ระบบรู้จักก่อนแท่งแตะเปิด ถ้าเพิ่งพบโซนหลังแท่งนั้นปิด จะไม่ย้อนกลับไปใช้โซนกับแท่งนั้น
- ถ้าต้นทางเปลี่ยนในนาทีที่แท่งแรกแตะ ระบบยังตรวจแท่งนั้นกับขอบที่รู้จักอยู่ก่อน เปลี่ยนเป็นขอบ frozen สำหรับ setup นี้ หากไม่มีการแตะ โซนที่หายจะถูกนำออก
- โซนที่ถูก rename แต่ขอบ เวลาเริ่ม และ timeframe เหมือนเดิมจะไม่สร้าง setup ซ้ำ ส่วน swing zone ใช้ความกว้างตอนพบครั้งแรก ไม่ขยายตาม ATR ภายหลัง
- setup ที่สิ้นสุดจะเริ่มรอบใหม่เมื่อมีแท่งปิดออกด้านเข้าหาโซน แล้วจึงรอการแตะใหม่; frozen zone ที่ต้นทางหายไม่เริ่มรอบใหม่
- มีแผน Active ได้หนึ่งแผนร่วมกันระหว่าง Strict และ M1 หาก Strict ออกก่อนในรอบเดียวกัน M1 จะบันทึก PLAN_ACTIVE; ถ้ามีหลายโซน M1 ยืนยันพร้อมกัน ใช้ลำดับโซนที่ลงทะเบียน ไม่ได้จัดอันดับคุณภาพเพื่อเลือกผู้ชนะ
- แผน M1 สิ้นสุดเมื่อเห็น SL, TP3 หรือครบ 30 นาที; Strict ยังคงอายุและ cooldown แบบเดิม แผนไม่ถูกเลื่อน Entry/SL/TP หลังออกสัญญาณ
- TP/SL เป็นเพียงการสังเกต quote ไม่ใช่ผล fill ของโบรกเกอร์ ยังไม่มี Win Rate, realized R หรือ Paper Performance ในรุ่นนี้
- ยังคงต้องอ่าน snapshot ของ H4/H1/M15/M5/M1 และ map SMC ได้ตาม adapter เดิม การเพิ่ม M1 lane ไม่ได้ข้ามความผิดพลาดของต้นทางหรือข้อมูล stale
- แผงที่ถูก restore มาจากการเปิด MT5 ใหม่สามารถถูกสร้างใหม่ได้เมื่อไม่มี instance ที่ถือสิทธิ์อยู่ ยังต้องถอดรุ่นเก่าก่อนติดตั้งรุ่นนี้ ไม่แก้สาเหตุทุกชนิดที่ทำให้ MT5 remove indicator

### การอ่าน ENTRY_CHECK

- `code=0`: ผ่านตัวคำนวณแผน
- `INVALID_STOP`, `RISK_TOO_SMALL`, `SPREAD_TOO_HIGH`: stop/ระยะเสี่ยง/spread ไม่ผ่าน
- `ENTRY_DEVIATION`: ราคาเข้าเคลื่อนจากราคาปิดแท่ง trigger เกินค่าที่กำหนด
- `ENTRY_INSIDE_OPPOSING_ZONE`: ราคาเข้าอยู่ในโซนฝั่งตรงข้าม เหลือ room เป็นศูนย์
- `INSUFFICIENT_ROOM_TP2`: พื้นที่ก่อนถึงโซนฝั่งตรงข้ามน้อยกว่า TP2_R × risk
- `TARGET_ROUNDING`: หลังปัดราคาให้ตรง tick แล้ว TP3 ไม่สามารถอยู่พ้น TP2 โดยยังเคารพขอบโซนได้

เหตุผลเดิม เช่น HTF_OBSTACLE ใน ZONE_END ยังเก็บไว้เพื่อเทียบ Audit เก่า โดย ENTRY_CHECK ให้รายละเอียดเพิ่มเติม Entry ใช้ Ask สำหรับ BUY และ Bid สำหรับ SELL ตามเดิม โซนกีดขวางอ่านจาก H4/H1/M15 และยกเว้นโซนต้นทางที่ยืนยัน breakout ตามเงื่อนไขเดิม

หน้าจอแสดงผล Entry ล่าสุดของทุกโมเดล พร้อม room เป็น R, required R, shortfall และชื่อโซน วางเมาส์บนบรรทัด Last entry/Room/Obstacle เพื่อดูรายละเอียดพร้อม setup_id ผลนี้อาจเป็นคนละ setup กับโซน Observer ที่เลือกอยู่ จึงใช้คำว่า Last entry แยกชัดเจน

หากไม่มีโซนขวางจะแสดง NONE และ room เป็น N/A ไม่ใช่ระยะเป็นศูนย์ ค่าราคาบนจอปัดตามจำนวนทศนิยมของ Symbol แต่ช่องตัวเลขคำนวณใน Decisions CSV เก็บละเอียดถึง 16 ตำแหน่งเพื่ออธิบายกรณีใกล้ขอบ เช่นจอแสดง 2.00R แต่ค่าจริงต่ำกว่า 2R เล็กน้อย รุ่นนี้ยังใช้การเปรียบเทียบและ rounding เดิม ไม่เปลี่ยนเกณฑ์ผ่านจากการปัดตัวเลขบนจอ

`gates` แสดงทุกเงื่อนไขที่คำนวณได้ ส่วนที่ขึ้นกับ risk ซึ่งผิดทิศเป็น N/A; rounding จะประเมินเมื่อผ่าน gate ก่อนหน้าแล้วเท่านั้น และ primary reason ใช้ลำดับเดิม

ENTRY_CHECK เกิดเฉพาะเมื่อเดินมาถึงขั้นประเมินราคาเข้าแล้ว ถ้ายัง WAIT_M5/WAIT_M1 หรือถูกบล็อกด้วยทิศ H1/Strict active/cooldown จะอ่านเหตุผลจาก Audit และสถานะขั้นนั้น ไม่สร้างแถว Entry ปลอม

### การอ่าน SOURCE_DETAIL

| Reason | ความหมาย |
|---|---|
| METADATA_CHANGED | key/ขอบโซนเดิม แต่ข้อความชื่อ เช่น Test Count เปลี่ยน ไม่ยกเลิก setup เพราะข้อความอย่างเดียว |
| BOUNDS_CHANGED | key เดิม แต่ low/high เปลี่ยนเกิน tolerance เดิมของ Observer 0.1 tick |
| ELIGIBILITY_CHANGED | ยังพบ object แต่ไม่ผ่านตัวกรอง เช่น Strength เปลี่ยน |
| POSSIBLE_RENAME | พบ candidate เดียวที่ TF/side/start/ขอบสอดคล้อง แต่ key ต่าง ยังไม่ต่อ setup อัตโนมัติ |
| AMBIGUOUS_MATCH | พบหลาย candidate ที่ตรง ห้ามเดาว่าเป็นโซนเดียวกัน |
| SOURCE_NOT_FOUND | รอบอ่านสมบูรณ์แต่ไม่พบ key/candidate เดิม ไม่ได้ยืนยันว่าถูกลบถาวร |
| SCAN_INCOMPLETE | ข้อมูลดิบอ่านไม่ครบหรือไม่พร้อม หากต้องยกเลิก Observer ใช้ DATA_RESET แทนการกล่าวว่าโซนเปลี่ยน |
| SOURCE_STRUCTURE_CHANGED | โครงสร้างที่ยืนยันไว้เปลี่ยนหรือไม่อยู่ใน accepted mapped events พร้อมข้อมูลเดิมและข้อมูลใหม่ที่หาได้ |

อ่าน rectangle ในรอบ scan เดิมก่อนกรอง Strength จึงเห็นโซนที่ถูกตัดออกด้วย ไม่ scan object ทั้งหมดซ้ำอีกรอบ การเปลี่ยน Strength และขอบพร้อมกันอาจได้ primary reason BOUNDS_CHANGED แต่ new_source ยังระบุ eligible/exclusion ประกอบ

ข้อมูล structure ใหม่เป็นข้อมูลที่ mapping ผ่าน ถ้าไม่พบจะระบุว่าไม่อยู่ใน accepted events ไม่อ้างว่าตัว object ถูกลบ เพราะอาจยังอยู่แต่ปิดแท่ง/label/สีไม่ผ่าน สำหรับชื่อที่เปลี่ยน ยังไม่มีระบบโอน identity หรือฟื้น setup ที่จบไปแล้ว

โซนของ Strict ใช้ SameZone เดิม (ขอบใน 1 tick, ไม่บังคับชื่อ) ส่วน Observer ใช้ WatchKey และ 0.1 tick เดิม รายละเอียดต้นทางจึงไม่ใช่เหตุให้ยกเลิก Strict เพิ่มขึ้นโดยตัวมันเอง

### เวลารอและความล่าช้า

- แผงแสดงอายุ cache ราย TF เป็น ms และ quote age เป็นวินาที
- Observer จะตรึงการเลือก setup ที่กำลังติดตามจนจบ เพื่อไม่ให้โซนใหม่ที่ใกล้กว่าดึงหน้าจอไปมา
- บรรทัด Selected event แสดงเหตุการณ์ล่าสุดของโซนที่เลือก; Last ended แสดง setup ล่าสุดที่จบ
- Strict/Observer deadline แสดงเวลาที่ต้องอ่านร่วมกับกฎเดิม: total/reaction หมดอายุเมื่อถึง limit; retest ยังรับแท่งที่ปิดตรง limit และจบเมื่อเลย limit การประเมินยังทำตามรอบแท่งเดิม ไม่ใช่ countdown ยกเลิกแบบ tick
- M5_CONFIRM/M1_BREAK/OBS_M5_CONFIRM/OBS_M1_BREAK มี `bar_closed_at`, `first_seen_at`, `detection_delay_s`, `decision_at`, `since_seen_s` และ `source_age_ms`
- first_seen คือครั้งแรกที่ตัวเสริมเห็น signature ที่ mapping ได้ในช่วงติดตามนี้ ไม่ใช่เวลาที่ Indicator ต้นทางสร้าง object และไม่ได้รับประกันว่าราคาเข้าที่เวลาปิดแท่งนั้นได้
- since_seen คือเวลาตั้งแต่พบ event ถึงบันทึกขั้นนั้น อาจรวมเวลารอเงื่อนไข จึงไม่ใช่ CPU processing time; scan time มีแยกอยู่แล้ว
- cache เวลาติดตามเฉพาะ event ในช่วงอายุสูงสุดของ setup และไม่เกิน 1,024 รายการต่อรอบ ส่วนเกิน/เก่าจะให้เวลา N/A การขาดข้อมูลจะล้าง cache นี้ และมีการตรวจ freshness/time budget หลังอัปเดต cache ก่อนประมวลผลสัญญาณ
- LATE_EVENT เป็นหลักฐาน candidate ที่พบหลังหมดอายุในขั้นรอ M5/M1 break แยก CLOSED_AFTER_DEADLINE กับ SEEN_AFTER_DEADLINE ไม่ได้บอกว่า candidate ผ่านกฎเข้าทั้งหมด และไม่สร้างสัญญาณย้อนหลัง

ทุกเวลาที่แสดงเป็นเวลา broker/server ไม่แปลงเป็นเวลาไทยอัตโนมัติ

### การตรวจสอบก่อนส่ง

ผ่านชุดทดสอบด้วย C++ harness ที่ดึงตรรกะจากซอร์ส: ลำดับ BUY/SELL เดิม, closed-bar mapping/cache, Observer rejection/breakout, เหตุผล Entry/source, CSV escaping/จำนวนคอลัมน์ และเปรียบเทียบสูตรใหม่กับสูตรเดิม 10,000 กรณี รวมถึงตรวจการเชื่อมต่อทั้งไฟล์ผ่านตัวแปลง C++

การตรวจเหล่านี้ **ไม่ใช่การ Compile ด้วย MetaEditor และไม่ใช่การรัน MT5 จริง** ยังต้องกด F7 ในเครื่องที่มี MT5 และตรวจ forward run อีกครั้ง ไม่มีผล backtest/กำไรที่รับรองจากการทดสอบซอฟต์แวร์นี้

ไฟล์ชุดซอร์สและ tests มีสคริปต์ Python 5 ตัว ต้องมี Python 3 และ g++ สำหรับการทดสอบตรรกะ ไม่จำเป็นต้องใช้ tests เพื่อติดตั้ง Indicator บน MT5

### ค่าตั้งต้นของ Observer

ค่าต่อไปนี้เป็นข้อกำหนดทดลองทางซอฟต์แวร์ ยังไม่ได้ปรับหาค่าที่ให้ผลตอบแทนดีที่สุด

| Input | ค่าเริ่มต้น | หน้าที่ |
|---|---:|---|
| EnableZoneTracker | true | เปิดการติดตามแบบ Observe Only ไม่มีตัวเลือกเปิดสัญญาณใหม่ในรุ่นนี้ |
| ShowZoneTracker | true | แสดงแผง Observer |
| ZoneConfirmATR | 0.05 | Buffer = ค่ามากกว่าระหว่าง 2 ticks และ 0.05 × ATR M5 |
| ZoneRetestATR | 0.10 | ระยะเผื่อแตะขอบตอน Retest = ค่ามากกว่าระหว่าง 1 tick และ 0.10 × ATR M5 |
| ZoneReactionBars | 6 | รอปฏิกิริยา 6 แท่ง M5 รวมแท่งที่แตะ แท่งที่ 7 หมดอายุ |
| ZoneRetestBars | 6 | ให้ Retest เกิดใน 6 แท่ง M5 ถัดจาก Breakout |
| ZoneObserveBars | 12 | อายุรวม 12 ช่วง M5 จากเวลาปิดแท่งแตะ รวมขั้นยืนยันโครงสร้าง/M1 |
| MaxTrackedZones | 64 | จำนวนโซน M15 สูงสุด ถ้าเกินจะหยุด Observer ด้วย ZONE_LIMIT ไม่สุ่มเลือกบางโซน |

ATR ใช้สูตรเดิมของโปรแกรม (ค่าเฉลี่ย True Range แบบ SMA) Buffer / ระยะ Retest / ระยะเผื่อ Stop ถูกตรึงเมื่อเริ่มแตะ ส่วนตัวกรองระยะ Entry และ M1 Retest ใช้ ATR ล่าสุดตามกฎเดิม เวลาอายุเหตุการณ์นับจากเวลาปิดแท่งตามเซิร์ฟเวอร์

### กฎปฏิกิริยาโซน

ให้ L = ขอบล่าง, U = ขอบบน, B = Buffer ค่าเปรียบเทียบเป็น strict: เท่ากับขอบรวม Buffer ยังไม่ยืนยัน

| ขั้น | โซนรับ | โซนต้าน |
|---|---|---|
| เตรียมรับการแตะ | เคยเห็น M5 ปิดเหนือ U+B หลังเริ่มติดตาม | เคยเห็น M5 ปิดต่ำกว่า L−B หลังเริ่มติดตาม |
| แตะ | High–Low ของแท่งปิดซ้อนกับ [L,U] | เหมือนกัน |
| กลับตัวจากโซน | M5 ปิดเหนือ U+B | M5 ปิดต่ำกว่า L−B |
| ทะลุโซน | M5 ปิดต่ำกว่า L−B | M5 ปิดเหนือ U+B |
| ทะลุแล้ว Retest Held | แท่งถัดไปแตะบริเวณ L แล้วปิดต่ำกว่า L−B | แท่งถัดไปแตะบริเวณ U แล้วปิดเหนือ U+B |
| Breakout Failed | หลังทะลุลง M5 ปิดกลับเหนือ L+B | หลังทะลุขึ้น M5 ปิดกลับต่ำกว่า U−B |

ไส้ทะลุแต่ราคาปิดในโซนคง IN_ZONE ราคากระโดดข้ามทั้งโซนโดยไม่มีแท่งซ้อนโซนเป็น GAP_CROSS และไม่สร้าง Setup หากเหตุการณ์จบ ต้องเห็นแท่งปิดนอกโซนทางฝั่งเริ่มต้นใหม่ก่อน แล้วค่อยยอมรับการแตะจากแท่งถัดไปเพื่อป้องกันนับซ้ำ

### ลำดับยืนยันและแผนสังเกตการณ์

**ZONE_REJECTION:** แตะ → ปิดออกทางฝั่งเริ่มต้น → M5 CHoCH ทิศเดียวกันที่ปิดหลังแท่ง Rejection → M1 BOS/CHoCH ใหม่ → M1 Retest ในแท่งถัดไป

**BREAKOUT_RETEST:** ปิดทะลุ → M5 BOS ทิศเดียวกัน และ Retest Held → M1 BOS/CHoCH ใหม่ → M1 Retest ในแท่งถัดไป

M5 BOS ของ Breakout ต้องปิดตั้งแต่แท่งที่ทะลุเป็นต้นไป และระดับเส้นต้องอยู่ที่ขอบที่ทะลุหรือเลยออกไปทางทิศทะลุ โดยเผื่อได้ไม่เกิน B จึงไม่รับ BOS เก่าหรือ BOS ที่ระดับไม่สัมพันธ์กับขอบนี้ Retest อาจเกิดก่อนพบ BOS ได้ แต่ต้องครบทั้งสองเงื่อนไขก่อนหา M1 Break ใหม่ M1 Break ต้องใหม่กว่าทั้งเวลาปิดโครงสร้าง M5 และเวลา Retest Held

เมื่อโครงสร้างครบแต่ H1 ไม่ตรงทิศ หรือ H4 ไม่ตรงเมื่อเปิด RequireH4Alignment เหตุการณ์นั้นจบด้วย ENTRY_BLOCKED ไม่รอเปลี่ยนทิศเพื่อเอา Setup เก่ามาใช้ เมื่อเส้นยืนยันหาย เปลี่ยนระดับ เวลา ทิศ หรือชนิด BOS/CHoCH จะยกเลิกเหตุการณ์

Stop ของ Rejection อ้างอิงจุดสุดขั้วตั้งแต่แตะจนยืนยัน ส่วน Breakout อ้างอิงจุดสุดขั้วของแท่งที่แตะบริเวณ Retest จน Retest Held และเผื่อด้วยกฎ ATR/Spread/Tick เดิม จากนั้นใช้ตัวกรอง Spread/Risk, ระยะ Entry, พื้นที่ถึงโซนขวางและการปัด Tick เดิม ถ้า Strict มีแผน Active หรืออยู่ใน Cooldown จะไม่ออก OBS_PLAN ของ Trigger นั้น

เมื่อผ่านครบ บันทึก `OBS_PLAN` พร้อมราคาสมมติ Entry/SL/TP1–TP3 จาก quote ใหม่ ณ ตอนตรวจ รุ่นนี้ไม่วาดแผน ไม่ส่ง Alert ไม่ติดตาม TP/SL ของ OBS_PLAN และไม่เปิดคำสั่งซื้อขาย จึงห้ามนับ OBS_PLAN เป็นออเดอร์หรือผลกำไร แต่ละ Setup บันทึกแผนได้ครั้งเดียว โซนที่ทับกันอาจมีหลาย Setup อิสระ ต้องแยกตาม Setup ID ในการวิเคราะห์

## อัปเดต v1.03: ตรวจข้อมูลค้างและลดงานสแกน

- อ่านเฉพาะชนิด Object ที่ใช้จับคู่โครงสร้างและโซน ลดการวนผ่าน Object ที่ไม่เกี่ยวข้อง
- เก็บผล H4/H1 ไว้สูงสุด 300 วินาที โดยอ่านใหม่เมื่อเปิดแท่ง TF ใหม่ เปลี่ยน Chart ID หรือหมดอายุ; M15 สูงสุด 60 วินาที, M5 สูงสุด 30 วินาที และ M1 อ่านใหม่ทุกรอบตรวจแท่งใหม่ การเปลี่ยนวัตถุในแท่ง H4/H1 เดิมอาจรอจน Cache หมดอายุ ไม่ใช่ข้อมูลสดทุก Tick
- แสดงเวลาสแกนล่าสุดเป็น `ms` ของแต่ละ TF และ `Data`/`last good age` บน Dashboard บันทึก `SCAN_BEGIN`/`SCAN_END` ช่วยหาว่า TF ใดช้า
- ตรวจราคาใหม่อีกครั้งหลังอ่านกราฟ ถ้าราคาเก่า ข้อมูลไม่ครบ แท่งเปลี่ยนระหว่างสแกน หรือเกินเวลาที่กำหนด จะขึ้น `STALE_*` และพักการสร้าง Entry เมื่อกลับมาพร้อมจะเริ่มรอ Setup ใหม่ ไม่สร้างสัญญาณย้อนหลัง
- `LIVE` หมายถึงรอบล่าสุดผ่านการตรวจและอยู่ในช่วงอายุข้อมูลที่อนุญาต ไม่ได้หมายความว่าทุก TF อ่านทุก Tick; ระหว่างสแกนขึ้น `SCANNING` ตัวเลขโครงสร้างที่ยังแสดงขณะ STALE เป็นค่าเดิม ไม่ใช่การยืนยันเข้าเทรด

ค่าเริ่มต้นใหม่: `HTFCacheSeconds=300`, `MaxFrameScanMs=1500`, `MaxCycleMs=8000`, `MaxQuoteAgeSeconds=15`, `LogScanTiming=true` หน้า Inputs อาจแสดงคำอธิบายภาษาอังกฤษแทนชื่อตัวแปร ดูค่าคู่กันในไฟล์ต้นฉบับ ไม่จำเป็นต้องเพิ่ม Inputs ที่ไม่มีในรุ่นเก่าเอง

ขีดจำกัดเวลาสแกนเป็นการตรวจระหว่างคำสั่ง ไม่สามารถยกเลิกคำสั่งอ่าน Object ของ MT5 ที่กำลังรออยู่ได้ ถ้าคำสั่งเดียวค้าง Dashboard/Timer ก็อาจยังอัปเดตไม่ได้จนคำสั่งนั้นคืนค่า รุ่นนี้ช่วยลดงานและระบุจุดช้า แต่ต้องตรวจความเร็วจริงใน MT5 ของคุณ

หลัง Compile และติดตั้ง ให้ดูหัว **v1.05**, `Last M1 scan (open)` ขยับตามแท่งใหม่ และ `SCAN_END` ของแต่ละ TF หากค้างหรือไม่มี Entry ให้ส่งบรรทัด `SCAN_BEGIN`, `SCAN_END`, `MAP_STATUS` และ `RESET` ช่วงนั้นมา บรรทัด `AUDIT_STATUS` ตอนเริ่มจะแจ้งชื่อ CSV หากเปิดบันทึก ไฟล์อยู่ใน Terminal Data Folder → MQL5 → Files

กฎ Entry/SL/TP และการรอแท่งปิดยังเหมือนเดิม ไม่เพิ่มสัญญาณก่อนยืนยัน การไม่มี Entry ขณะข้อมูล LIVE อาจเกิดจาก Setup ยังไม่ครบ ตรวจ `ZONE_CHECK` และ Stage ประกอบ

ทดสอบตรรกะด้วยชุดจำลองภายนอก MT5; ยังไม่ได้ Compile ด้วย MetaEditor หรือทดสอบกราฟจริงในสภาพแวดล้อมนี้

## อัปเดต v1.02: ตรวจว่า WAIT_ZONE ทำงานอยู่หรือไม่

เพิ่ม `ShowDiagnostics=true` และ `LogZoneChecks=true` เป็นค่าเริ่มต้น แสดงผลตรวจล่าสุดบน Dashboard และบันทึก `ZONE_CHECK` ใน Experts ทุกครั้งที่ประเมินแท่ง M5 ปิดใหม่ใน Stage `WAIT_ZONE` หากเปิด `WriteAuditCSV=true` จะมีรายการเดียวกันใน Audit ด้วย ไม่แจ้งเตือน Popup ทุกแท่ง

กฎ Entry/SL/TP คงเดิม: ต้องแตะโซนและ Sweep ในแท่ง M5 เดียวกัน และผ่านตัวกรองเดิมทั้งหมด การตรวจแยกแต่ละข้อช่วยให้รู้สาเหตุ ไม่ได้ผ่อนเงื่อนไขเพื่อเพิ่มสัญญาณ

### ติดตั้งและตรวจจริง

1. ถอดเฉพาะ `SMC_SR_MTF_Signals` เดิมจาก M1 แทนไฟล์ `.mq5` ชื่อเดิม แล้ว Compile ด้วย F7 ใส่กลับบน M1 และตรวจหัวว่าเป็น **v1.05** การถอดจะล้างแผนเดิมและเริ่ม Session ใหม่
2. คงกราฟ H4/H1/M15/M5/M1 และ Indicator ต้นทางทั้งสองในทุกกราฟ ตั้ง `ShowDiagnostics=true`, `LogZoneChecks=true`, `WriteAuditCSV=true`
3. ขยายหน้าต่างกราฟ **M1 ให้เต็มพื้นที่** เพื่ออ่านข้อความตรวจสอบใต้แผน ระหว่างนี้กราฟต้นทางอีกสี่กราฟยังต้องเปิดอยู่ ไม่จำเป็นต้องแสดงทั้งหมดแบบแบ่งหน้าจอ
4. ตรวจ `Timer #` ว่าเพิ่มขึ้น ตัวเลขนี้ยืนยันเพียงว่า Timer ของตัวเสริมยังทำงาน ไม่ใช่หลักฐานว่ามีราคาใหม่หรือเชื่อมต่อโบรกเกอร์ปกติ
5. เมื่อมีข้อมูลใหม่และอ่านต้นทางครบ `Last M1 scan (open)` ควรขยับตามแท่ง M1 ใหม่ หากค้าง ให้ดู Status หลักและสถานะ TF เพื่อหาประวัติ/ต้นทางที่ติด
6. ขณะ Stage `WAIT_ZONE` และไม่มีตัวกรองอื่นกั้น `Last zone check M5 (open)` ควรขยับเมื่อมีแท่ง M5 ปิดใหม่ เช่น แท่งเปิด 10:00 จะถูกประเมินหลัง 10:05 ตามเวลาเซิร์ฟเวอร์ ไม่ประเมินแท่งกำลังก่อตัว และไม่ประเมินย้อนหลังทันทีตอนเริ่ม Session
7. อ่าน `Last check` และผลแต่ละข้อ หรือคัดลอกบรรทัด `SMC MTF | ZONE_CHECK | ...` จาก Experts หากทุกข้อผ่าน Stage จะเปลี่ยนเป็น `WAIT_M5_CHOCH` พร้อมบันทึก `SWEEP`

v1.02 ทดสอบฟังก์ชันจากซอร์สจริงผ่าน C++ harness ด้วยข้อมูล/ส่วน I/O จำลอง: ลำดับ BUY/SELL เดิมยังผ่าน, ไม่ประเมิน WAIT_ZONE ระหว่างแท่ง M5, ผลเหตุผลแต่ละชนิดและการเปิด/ปิด Log ผ่านแล้ว **ยังไม่ได้ Compile ใน MetaEditor หรือรันใน MT5 จริงจากสภาพแวดล้อมนี้**

## อัปเดต v1.01 สำหรับ `No confirmed mapped structure`

ข้อความเดิมหมายถึงตัวเสริมยังหาโครงสร้างที่จับคู่เส้น สี ป้าย และแท่งปิดได้ไม่ครบอย่างน้อยหนึ่ง TF จึงพักการสร้างสัญญาณ ไม่สามารถสรุปจากข้อความนี้เพียงอย่างเดียวว่าตลาดไม่มี BOS/CHoCH หรือเป็น Sideway

- เพิ่ม `StructureHistoryBars=2000` สำหรับอ่านโครงสร้าง แยกจาก `HistoryBars=300` ที่ใช้หา Pivot/ATR เดิม หากเส้นล่าสุดอยู่นอก 300 แท่งแต่ยังอยู่ในช่วงใหม่ จะตรวจแท่งปิดของเส้นนั้นได้ ทั้งนี้ยังไม่ยืนยันว่านี่เป็นสาเหตุของสถานะล่าสุดบนเครื่องคุณ
- ต้องโหลดแท่งปิดให้ครบ `StructureHistoryBars` ต่อ TF ก่อนประเมิน หากประวัติยังไม่ครบจะแสดง `LOADING_HISTORY` และจำนวนที่อ่านได้ในรายละเอียด ไม่ใช้ข้อมูลบางส่วนโดยเงียบ ๆ
- แสดงสถานะแยก H4/H1/M15/M5/M1 พร้อมรายละเอียดเมื่อชี้เมาส์ที่ข้อความ และบันทึก `MAP_STATUS` ใน Experts/Audit เมื่อรหัสสถานะเปลี่ยน ขณะ `[not ready]` ข้อมูล TF ที่อ่านได้เป็นข้อมูลตรวจสอบ ยังไม่พร้อมออกสัญญาณ
- `MaxObjectsToScan` ค่าเริ่มต้น 20,000 นับเฉพาะวัตถุ `iSMC_str_line_`, `iSMC_str_lbl_`, `SSSR#` แทนการนับวัตถุทุกชนิดในกราฟ เมื่อข้อมูลไม่พร้อม ลองอ่านใหม่ทุกประมาณ 10 วินาที
- กฎ Entry/SL/TP และการตรวจแท่งปิดคงเดิม ยังต้องอ่านโครงสร้างได้ครบทั้ง 5 TF แม้ปิด `RequireH4Alignment` อยู่ ไม่สร้างสัญญาณชดเชยช่วงข้อมูลขาด

ค่าการอ่านโครงสร้างจาก v1.01 ยังใช้ใน v1.02: `StructureHistoryBars=2000` และ `MaxObjectsToScan=20000` เก็บ Indicator ต้นทางและกราฟทั้งห้าไว้ตามเดิม

## ติดตั้ง

1. ใน MT5 เปิด **File → Open Data Folder → MQL5 → Indicators** แล้ววาง `SMC_SR_MTF_Signals.mq5` (ตัวนี้อยู่ใน Indicators ไม่ใช่ Scripts)
2. เปิดไฟล์ด้วย MetaEditor แล้วกด F7 เพื่อ Compile หากเกิด Error ให้ส่งข้อความจากแท็บ Errors กลับมา
3. เปิดกราฟ **สินทรัพย์เดียวกัน 5 หน้าต่างแยกกัน** ตั้งเป็น **H4, H1, M15, M5, M1** และเปิดค้างไว้ มีเพียงหนึ่งหน้าต่างต่อ TF สำหรับสินทรัพย์นี้ ไม่ใช่เปลี่ยน TF ไปมาบนหน้าต่างเดียว
4. ใส่ `Smart Money Concepts` และ `Pro Support Resistance MT5` เดิมลงในทุกหน้าต่างด้วยค่าตั้งเดิมที่ใช้ส่งผลตรวจ รอข้อมูลแสดงครบ หาก Indicator มีตัวเลือก Timeframe ภายใน ให้ใช้ TF ของกราฟนั้นก่อน เวอร์ชันนี้ยังตรวจค่าภายใน EX5 ไม่ได้
5. ใน Navigator → Indicators ให้ Refresh แล้วลาก `SMC_SR_MTF_Signals` ลงเฉพาะหน้าต่าง **M1** ใช้ค่าเริ่มต้นได้
6. Dashboard จะค้างบนกราฟและรอสัญญาณใหม่ ส่วนเส้น Entry/SL/TP จะปรากฏเมื่อเงื่อนไขครบ ไม่มีการสร้างลูกศรย้อนหลังตอนเริ่มต้น จึงอาจต้องรอหลายชั่วโมงหรือไม่พบ Setup ในช่วงที่เปิดใช้งาน

ไม่ต้องใช้ไฟล์ CSV วางใน MT5 เพื่อให้ตัวเสริมทำงาน และไม่จำเป็นต้องติดตั้ง ZigZag/RSI สำหรับตรรกะของตัวเสริมนี้ สามารถเก็บ Indicator เหล่านั้นตามเดิมได้

ชื่อสินทรัพย์ต้องเหมือนกันทุกตัวอักษร เช่น `GOLD` ทั้ง 5 หน้าต่าง ไม่ผสม `GOLD`, `GOLDm`, `XAUUSD` ในชุดเดียว โปรแกรมอ่าน Symbol จากกราฟ M1 ที่ติดตั้ง ไม่ได้ล็อกชื่อ GOLD แต่ตรวจข้อมูลรูปแบบวัตถุจาก GOLD เท่านั้น ยังไม่ได้ทดสอบกับ BTC หรือสินทรัพย์อื่น

## สิ่งที่ตรวจพบจากไฟล์ของคุณ

- H4, H1, M15, M5 และ M1 มีชื่อ Indicator และรูปแบบวัตถุที่สอดคล้องกัน
- ใช้ `iSMC_str_line_...` คู่กับ `iSMC_str_lbl_...` เพื่ออ่านเส้น BOS/CHoCH โดยเทียบราคา สี และช่วงเวลา
- เวลาป้ายมักอยู่กลางเส้น จึงใช้ปลายเส้นด้านขวาเป็นผู้สมัครเวลาเบรก แล้วตรวจว่ามีแท่งเวลานั้นปิดและราคาปิดอยู่ฝั่งที่เบรกจริง หลีกเลี่ยงการใช้เวลาป้ายเป็นเวลาเข้า
- สีที่สังเกตจากไฟล์: Bull = RGB(8,153,129), Bear = RGB(242,54,69) เปลี่ยนได้ที่ Inputs หากคุณเปลี่ยนสีต้นทาง ต้องปรับสองค่านี้ตาม
- ใช้กล่อง `SSSR#S...` เป็น Support และ `SSSR#R...` เป็น Resistance รับเฉพาะ Strength `Verified` และ `Un-Mitigated` ซึ่งพบในผลตรวจ ใช้ขอบราคาจากกล่อง ไม่ใช้ตำแหน่งข้อความหรือเส้น FVG
- ไม่มีการนำหมายเลข Buffer ที่ยังไม่ทราบความหมายมาเดาเป็นสัญญาณ และไม่ได้แก้ไขหรือถอดรหัสไฟล์ EX5
- CSV แต่ละ TF ถูกส่งออกคนละเวลา จึงใช้ตรวจรูปแบบการเชื่อมข้อมูล ไม่ใช่ชุดข้อมูลพร้อมกันสำหรับ Backtest

## กฎสัญญาณเวอร์ชันนี้

กฎต่อไปนี้เป็นข้อกำหนดตั้งต้นสำหรับทดลอง ยังไม่มีผลทดสอบกำไร ขาดทุน หรือ Win rate

| TF | หน้าที่ |
|---|---|
| H4 | แนวรับ/ต้านที่ขวางเป้าหมาย; เปิดตัวกรองให้ทิศตรง H1 ได้ |
| H1 | กำหนด BUY/SELL จากโครงสร้าง BOS/CHoCH ล่าสุดที่จับคู่ได้และยืนยันด้วยแท่งปิด |
| M15 | เลือกโซน Support สำหรับ BUY / Resistance สำหรับ SELL |
| M5 | แตะโซนและ Sweep จากนั้นรอ CHoCH ไปทางเดียวกับ H1 |
| M1 | รอ BOS หรือ CHoCH ใหม่หลัง M5 ยืนยัน แล้วรอแท่งถัดไปกลับทดสอบและปิดยืนยัน |

ลำดับ BUY:

1. H1 ล่าสุดเป็น Bullish
2. แท่งปิด M5 ทับซ้อน Support M15 และแทงต่ำกว่า Swing low M5 ล่าสุดที่ยืนยันแล้ว ก่อนปิดกลับเหนือ Swing low นั้น โดยราคาปิดไม่ต่ำกว่าขอบล่างโซน
3. ต้องเกิด M5 CHoCH ขึ้นหลังแท่ง Sweep ปิด (คนละเหตุการณ์ ไม่ใช้เวลาเดียวกัน)
4. ต้องเกิด M1 BOS/CHoCH ขึ้นใหม่หลัง M5 ยืนยัน และตัวเสริมเห็นเหตุการณ์นั้นเมื่อแท่งดังกล่าวเพิ่งปิด
5. แท่ง M1 ถัดไปแตะระดับเบรกภายในระยะยอมรับ ปิดเหนือระดับ และ Close > Open
6. ผ่านตัวกรองระยะ SL, Spread, ระยะห่างจากแท่ง Trigger และโซนที่ขวาง TP2 จึงออกสัญญาณ

SELL กลับทิศทุกข้อ โดย Sweep สูงกว่า Swing high แล้วปิดกลับต่ำกว่า, M5 CHoCH ลง, M1 เบรกลง, Retest แล้ว Close < Open

Swing M5 ใช้ Pivot ที่สูง/ต่ำกว่าแท่งข้างเคียงอย่างชัดเจน ซ้าย 3 ขวา 3 แท่ง และต้องยืนยันเสร็จก่อนแท่ง Sweep ไม่ใช้ ZigZag ล่าสุดเป็น Pivot ที่ยืนยันแล้ว

Premium/Discount และ RSI ยังไม่ใช่ตัวกรองในเวอร์ชันนี้ เพราะยังไม่มีการยืนยันความหมายของ Buffer ช่วงอ้างอิง ไม่ได้ให้ทุก TF โหวตพร้อมกัน: H1 เป็นตัวกำหนดฝั่ง; H4 บังคับทิศได้ด้วย `RequireH4Alignment`

## Entry, SL และ TP

- **Entry:** Ask ตอนออก BUY / Bid ตอนออก SELL หลังแท่งยืนยันปิด เป็นราคาอ้างอิงที่สังเกตได้ ไม่ใช่การรับรองว่าจะส่งคำสั่งได้ราคานั้น
- **SL BUY:** ต่ำกว่า Low ของ Sweep M5; **SL SELL:** สูงกว่า High ของ Sweep M5
- ระยะเผื่อ SL = ค่ามากสุดระหว่าง `0.15 × ATR M5`, `2 × Spread` และ `2 × Tick size` คำนวณและล็อกเมื่อจับ Sweep
- ATR ในโค้ดเป็นค่าเฉลี่ยธรรมดาของ True Range 14 แท่งปิด (SMA) จึงอาจต่างจาก ATR ที่ใช้ Wilder smoothing
- ระยะเสี่ยง `R = |Entry − SL|`
- **TP1 = 1R, TP2 = 2R, TP3 = 3R** เป็นค่าตั้งต้นที่เปลี่ยนได้ใน Inputs รุ่นนี้เลือกเป้าระยะ R เพื่อให้ตรวจสูตรได้ชัดเจน แทนการอ้างว่าอ่าน Swing target ทั้งหมดจาก Buffer เดิมได้
- ตรวจโซนฝั่งตรงข้ามของ M15/H1/H4: ถ้า Entry อยู่ในโซนดังกล่าว หรือพื้นที่ก่อนถึงโซนไม่พอ TP2 จะข้ามสัญญาณ
- ถ้าโซนขวางระหว่าง TP2 กับ TP3 จะลด TP3 ให้อยู่ก่อนขอบโซนพร้อมเผื่อ Spread อย่างน้อยหนึ่ง Tick บางกรณี TP3 อาจเท่ากับ TP2 หลังปัดราคา
- ข้ามเมื่อ Spread เกิน 20% ของ R หรือ Entry ต่างจากราคาปิด Trigger มากกว่า 0.5 ATR M5
- เมื่อออกสัญญาณแล้ว Entry/SL/TP จะคงที่ ไม่มีเลื่อน SL ไป BE, ไม่มี Trailing stop และไม่มีการแบ่งปิดออเดอร์อัตโนมัติ

รองรับแผนที่กำลังติดตามหนึ่งแผนต่อ Instance รอจนสังเกตว่าแตะ SL หรือ TP สุดท้าย แล้วพัก 10 นาที ก่อนรับ Setup ใหม่ เส้นแผนล่าสุดค้างไว้จนมีแผนใหม่ ลูกศรสะสมเฉพาะระหว่างที่ Indicator ยังเปิดอยู่

## ยกเลิก Setup เมื่อใด

- H1 เปลี่ยนทิศ หรือ H4 ไม่ตรงเมื่อเปิดตัวกรอง H4
- ราคาแตะ SL ก่อนเข้า, ราคาปิด M5 ทำลายขอบโซน, ขอบ/ตัวตนของโซนเปลี่ยนหรือหาย
- เส้นยืนยันที่อ้างอิงหาย หรือราคา/เวลา/ทิศของเส้นเปลี่ยน
- รอนานเกิน 12 แท่ง M5 นับจากการรับ Sweep หรือรอ Retest นานเกิน 10 แท่ง M1
- ข้อมูลขาดช่วง, ปิดกราฟต้นทาง, ถอด Indicator ต้นทาง, เปิด TF ซ้ำจนเลือกต้นทางไม่ได้
- หลังเชื่อมข้อมูลกลับมา จะเริ่มรอ Setup ใหม่ ไม่ย้อนสร้างลำดับเหตุการณ์ช่วงที่ขาด

| `SL observed` / `Final TP observed` | สังเกตจากราคา quote ไม่ใช่ผลปิดออเดอร์จริง |

โปรแกรมตรวจข้อมูลต้นทางเมื่อแท่ง M1 ใหม่เริ่มไปแล้วอย่างน้อย 2 วินาที ใช้แท่งปิดเท่านั้น Dashboard และการติดตาม quote ใช้ Timer ประมาณ 2 วินาที จึงอาจพลาดการแตะแล้วเด้งอย่างรวดเร็วระหว่างรอบ Timer ห้ามใช้จำนวน TP/SL ที่แสดงเป็นผล Backtest หรือสถิติการเทรด

รายละเอียด `MAP_STATUS`: `lines`/`labels` คือจำนวนเส้น/ป้ายที่รองรับ, `accepted` คือจำนวนที่ยืนยันได้, `old` คือเส้นเกินช่วงย้อนหลัง, `no_closed_bar` คือเวลาไม่ตรงแท่งปิด, `color`/`close`/`label`/`shape`/`time` คือจำนวนที่ไม่ผ่านแต่ละขั้น และ `range` คือช่วงเวลาแท่งที่โหลดได้ แต่ละเส้นนับเฉพาะขั้นแรกที่ไม่ผ่าน เมื่อมีหลายสาเหตุพร้อมกัน Dashboard แสดงหนึ่งรหัส ให้ดูจำนวนทั้งหมดประกอบ หากยังติด ให้คัดลอกบรรทัด `SMC MTF | MAP_STATUS | ...` ของ TF นั้นจากแท็บ Experts

## แจ้งเตือนและไฟล์ตรวจสอบ

- `PopupAlerts=true` เปิดหน้าต่างแจ้งเตือนเมื่อเกิด Signal
- `PushAlerts=false` เป็นค่าเริ่มต้น หากต้องการส่งเข้ามือถือ ต้องตั้งค่า Notifications ของ MT5 เอง แล้วเปิดค่านี้
- Audit อยู่ใน **File → Open Data Folder → MQL5 → Files** ชื่อ `SMC_MTF_Audit_...csv`
- บันทึกเหตุการณ์เริ่มต้น โครงสร้างที่อ่านได้ Sweep/CHoCH/Break/Signal/การยกเลิก และระดับที่สังเกตว่าแตะ
- ถ้าพบปัญหา ส่งภาพ Dashboard, Experts และ Audit CSV พร้อมภาพกราฟในช่วงเดียวกัน

## การตรวจและข้อจำกัด

ตรวจรูปแบบวัตถุกับ CSV จริงครบ 5 TF: พบเส้นล่าสุดที่จับคู่ป้ายได้และมีราคาปิดทะลุระดับตรงตามสีในข้อมูลตัวอย่างทั้งหมด การตรวจนี้ยืนยันการจับคู่ในตัวอย่าง ไม่ยืนยันพฤติกรรม Indicator ทุกสภาวะ

ทดสอบฟังก์ชันตรรกะที่ดึงจากซอร์สจริงในชุดทดสอบ C++ โดยแทนส่วน I/O ของ MT5: สูตรเป้า BUY/SELL, การปัด Tick, ตัวกรอง Spread/ระยะ Entry/โซนขวาง, Pivot ที่ยืนยันก่อน Sweep, ATR, ลำดับ Sweep→CHoCH→Break→Retest ทั้งสองฝั่ง, ห้ามใช้แท่ง Break เป็น Retest, ป้องกัน Signal ซ้ำขณะแผน Active, การหมดอายุและต้นทางหาย ผ่านการทดสอบเหล่านี้แล้ว

v1.01 เพิ่มการทดสอบฟังก์ชันอ่านโครงสร้างจริงด้วย API จำลอง: อ่านเส้นเก่ากว่า 300 แท่งได้เมื่อขยายหน้าต่าง, เวลาแท่งต้องตรงแบบ exact, ปฏิเสธแท่งกำลังก่อตัว/ประวัติไม่ครบ/สีผิด/ป้ายไม่ตรง/ราคาปิดไม่ยืนยัน/ทิศขัดกัน, ไม่นับวัตถุที่ไม่เกี่ยวข้องในขีดจำกัด และรายงานข้อผิดพลาดครบทุก TF ผ่านการทดสอบเหล่านี้แล้ว

**ยังไม่ได้ Compile ด้วย MetaEditor หรือรันทดสอบบน MT5 จริงในสภาพแวดล้อมผู้สร้าง** ชุดทดสอบ C++ ไม่ทดแทน MQL5 compiler หรือพฤติกรรม API ของ MT5 จัดส่งเฉพาะซอร์ส `.mq5` ให้คุณ Compile เอง ไม่มี `.ex5` ที่ทดสอบแล้ว

Indicator ต้นทางอาจแก้เส้น/โซนย้อนหลัง แม้ใช้แท่งปิดแล้วก็ยังรับประกัน Non-repaint ไม่ได้ ตัวเสริมล็อกแผนที่ออกไปแล้วและยกเลิก Setup ที่ยังไม่เข้าเมื่อพบต้นทางเปลี่ยน การปิด/เปิดใหม่ เปลี่ยน Inputs หรือ TF จะเริ่ม Session ใหม่ ไม่กู้แผนเดิมอัตโนมัติ Audit เก็บไว้ แต่รูปวาดของตัวเสริมจะถูกล้างเมื่อถอดออก

เวอร์ชันนี้พึ่ง Chart objects จากกราฟต้นทางที่เปิดอยู่ จึง **ไม่รองรับ Backtest แบบ Strategy Tester กราฟเดียวโดยตรง** ต้องพัฒนาเวอร์ชันบันทึกข้อมูล ณ เวลาเกิดจริง หรือย้ายตรรกะต้นทางมาอยู่ในระบบทดสอบก่อน จึงจะประเมินผลย้อนหลังอย่างน่าเชื่อถือได้

เริ่มด้วย Demo/Forward test และเทียบเส้นที่ระบบอ่านกับกราฟจริงก่อนใช้ประกอบการตัดสินใจ ยังไม่มีหลักฐานว่ากฎตั้งต้นนี้ทำกำไรได้
